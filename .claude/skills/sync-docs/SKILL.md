# 문서 동기화 워크플로우

코드 변경이 끝난 뒤, 저장소의 문서(docs/, CLAUDE.md, .claude/)와 코드 내 서술(javadoc, 로그 문자열)이 새 구조와 어긋난 곳을 전수 스캔해 갱신한다.

## 0. 변경 어휘 추출

문서를 읽기 전에, 이번 작업으로 **이름이 바뀌거나 사라진 것들의 목록**을 먼저 만든다.

1. 기준 diff 확정: 인자가 없으면 `git diff main...HEAD --stat` (작업 중이면 워킹 트리 포함).
2. diff에서 추출할 것:
   - 개명/이동된 클래스·파일 (`git diff --stat`의 `rename`, `git log --diff-filter=R`)
   - 삭제된 클래스·메서드·이벤트·빈
   - 책임이 이동한 메서드 (A 클래스에서 B 클래스로 옮겨진 public 메서드)
   - 새로 생긴 핵심 컴포넌트
3. 결과를 "구 이름 → 새 이름/행방" 매핑 표로 정리한다. 이 표가 이후 모든 grep의 검색어다.

## 1. 문서 분류 — 고칠 문서와 보존할 문서

**이 저장소의 문서는 두 종류이며, 취급이 다르다:**

| 분류 | 위치 | 취급 |
|---|---|---|
| **현행 문서** (living) | `docs/core/*`, `CLAUDE.md`, `.claude/agents/*`, `.claude/skills/*` | 본문을 현재 구조에 맞게 **직접 수정** |
| **시점 기록** (point-in-time) | `docs/design/*`, `docs/refactoring/*`, `docs/reviews/*` | 본문은 **수정하지 않는다** — 작성 시점의 판단 기록을 고치면 이력이 훼손된다 |

시점 기록 중 **코드 javadoc이 참조하는 문서**(예: 설계 문서 경로가 코드 주석에 박혀 있는 것)는 독자가 길을 잃지 않도록 **문서 상단에 개명 매핑 노트만 추가**한다:

```markdown
> **[YYYY-MM 이후 클래스 개명]** 이 문서의 클래스명은 작성 시점 기준이다. 이후 ...로
> `구클래스` → `새클래스A`(역할) + `새클래스B`(역할)로 재편됐다.
```

- 어떤 시점 기록에 노트를 달지는 코드에서 역참조로 판단: `grep -rn "docs/" src/main --include="*.java"`로 참조되는 문서만 대상.
- 이미 같은 성격의 노트가 있으면 새로 달지 말고 기존 노트에 이어 쓴다.

## 2. 전수 스캔

0단계 매핑 표의 **구 이름 각각**에 대해 검색한다. 문서만이 아니라 코드 내 서술도 스캔 대상이다.

```bash
# 1) 문서
grep -rn "구이름" docs CLAUDE.md .claude --include="*.md"

# 2) 코드 내 서술 — javadoc, 주석, 로그 문자열 (컴파일은 통과해도 서술은 낡는다)
grep -rn "구이름" src/main src/test --include="*.java"
```

주의할 함정 (실제로 겪은 것들):
- **로그 문자열**: `log.warn("구클래스명: ...")` 같은 접두어는 컴파일 에러가 안 나므로 grep으로만 잡힌다.
- **상호 참조 주석**: "X는 Y가 담당" 류의 다른 클래스 javadoc 속 서술.
- **문서 속 파일 경로·라인 번호**: `Foo.java:58` 같은 참조는 파일 개명 시 함께 낡는다. 현행 문서면 새 경로(가능하면 라인 번호 대신 메서드명)로 교체.
- **테스트 클래스명 참조**: "검증은 FooTest가 덮는다" 류의 javadoc.

## 3. 갱신 원칙

- **현행 문서**: 새 구조를 사실대로 서술. 큰 구조 변경이면 기존 서술을 지우기보다 `[YYYY-MM ~ 이후]` 어노테이션 블록을 추가하는 저장소 관례를 따른다 (docs/core/03-architecture.md의 기존 패턴 참조).
- **docs/core/06-refactoring-notes.md**: 과거 현황 서술은 지우지 말고 `(→ 이후 ...로 분리/개명)` 꼬리표를 붙인다. 이번 작업으로 완료된 체크리스트 항목이 있으면 `[x]` 갱신.
- **의도적 이력 표기는 남긴다**: 새 클래스 javadoc의 `(구 OldName)` 같은 표기는 낡은 참조가 아니라 안내다 — 지우지 않는다.
- 문서에 없는 내용을 새로 창작하지 않는다. 이번 변경으로 **틀려진 서술만** 고친다.

## 4. 검증

갱신 후 잔존 참조를 재검색해서, 남은 것이 전부 의도된 것인지 확인한다:

```bash
grep -rn "구이름1\|구이름2\|..." src docs CLAUDE.md .claude --include="*.java" --include="*.md"
```

남아도 되는 것: `(구 ...)` 이력 표기, 시점 기록 본문, 개명 매핑 노트 자체.
그 외가 남아 있으면 누락이다.

## 5. 커밋

- 문서 변경은 **별도 커밋**으로 분리한다 (split-pr 규칙 6번 카테고리와 동일).
- 코드 커밋에 이미 문서가 섞여 들어간 상태라면 그대로 두되, 추가 갱신분만 새 커밋.
- 메시지 컨벤션: `[SGMR-X] 문서 동기화 — {무엇의 개명/변경 반영}` + `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
- 열려 있는 PR이 있으면 푸시로 반영하고, PR 본문의 변경사항 설명도 낡았으면 `gh pr edit`로 갱신한다.
